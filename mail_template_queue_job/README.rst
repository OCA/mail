Some emails are posted automatically while the user is doing something
else: the delivery confirmation when a transfer is validated, the
confirmation of a sales order, a rating request... Rendering the reports
attached to those emails can take a few seconds, and the user has to
wait for it before the operation finishes.

This module adds an option to email templates to post those messages in
a queue job instead, so the operation does not wait for the email. Only
the message of the template is delayed: everything else done by the
operation still runs as usual.

Configuration
=============

1. Go to *Settings > Technical > Email > Email Templates* and open a
   template, for example *Shipping: Send by Email*.
2. In the *Settings* tab, enable *Post in a Queue Job*.

Usage
=====

1. Do the operation that posts the template automatically. With the
   example above, enable *Email Confirmation* in the Inventory settings
   and validate a delivery order.
2. A job *Post ... on ...* is created for each record. Once it is done,
   the email appears in the chatter of the record.

The option only applies to messages posted by the code with the template
(the ``message_post_with_source`` method). Emails sent by the user from
the composer, and mass mailings, are not affected.

Known issues / Roadmap
======================

- Jobs only keep a few keys of the context (language, timezone,
  companies). The keys that decide when the email is sent
  (``force_send`` and ``mail_notify_force_send``) are carried to the
  job, but a template rendered from other context values would get them
  empty. Other modules can extend
  ``_message_post_with_source_job_context_keys`` to carry more keys.
- The code posting the template gets no message back, as it is created
  later by the job.
- Odoo already provides ``sale_async_emails`` to send the sales order
  confirmation email from a scheduled action. Use one or the other for
  that template.
